# ブラウザ版の使い方

アプリを入れずに、端末のブラウザで URL を開くだけで使う。判定は PC 側が行い、
端末はカメラとスピーカーだけを担う。

## 起動（PC 側）

Windows:

```bat
scripts\setup.bat     :: 初回だけ。venv と依存を入れる
scripts\demo.bat
```

その他:

```bash
python -m alertness.demo
```

引数は要らない。IP の検出も証明書の作成も自分でやり、端末で開く URL と手順を
実際のアドレスで表示する。

```
============================================================
  端末のブラウザで次を開いてください
      https://192.168.1.10:8765/

  1. 証明書の警告を承認する（「詳細」→「アクセスする」系）
  2. 言語を選んで「はじめる」→ カメラを許可
  3. 端末を固定し、完了の音が鳴るまで前方を見る（基準の測定）

  同じ Wi-Fi にいること。繋がらないときはファイアウォールで
  8765 の受信を許可してください。終了は Ctrl+C。
============================================================
```

**案内の後は、人が対応すべき異常が起きない限り何も出さない。** 端末の接続・切断や
MediaPipe の内部ログは、繋がらないときの切り分けにしか使わないので、
`scripts\demo.bat --verbose` を付けたときだけ出す。常に出るのは次の 2 つ。

| 出力 | 意味 |
|---|---|
| `[異常] 判定が N 秒とまっています` | 端末は繋がっているのに判定が流れていない |
| `[警告] フレームの解析に失敗しました` | 検出器が落ちた。続くと終了する |

**IP が変わったら証明書も自動で作り直す。** ブラウザはアドレスと一致しない証明書を
拒むので、放置すると「ページは開けるのにカメラが出ない」という原因の見えない失敗に
なる。作り直したときは案内の中にその旨が出るので、端末で承認をやり直す。
証明書には PC の IPv4 アドレスを全部入れてあり、有線と Wi-Fi の両方を持つ PC では
案内に「開けないときは」として別の URL も並ぶ。どれで開いても承認は 1 回で済む。

検出した IP が端末から届かないとき（VPN 接続中など）は、環境変数か設定で指定する。

```bat
set ALERTNESS_HOST=192.168.1.10
scripts\demo.bat
```

`config/browser.yaml` の `source.remote.advertise_host` に書いてもよい。

証明書と秘密鍵（`certs/`）は PC ごとに作るもので、git には入れない。

収録するときは通常の入口を使う。

```bash
python -m alertness --config config/browser.yaml ^
  --guided --protocol acted_long --rounds 1 --record --subject <名前>
```

**ファイアウォールで 8765 の受信を許可しておく。** Windows では初回起動時に
ダイアログが出るので「アクセスを許可する」を選ぶ。ここで詰まると「繋がらない」
としか見えない。

終了は Ctrl+C。検出器の中で固まって止まらないときは、もう一度 Ctrl+C を押す。

## 接続（端末側）

1. ブラウザで `https://<PCのIP>:8765/` を開く
2. 証明書の警告を承認する（初回だけ）
3. `JP`（日本語）または `EN`（英語）を選ぶ（初回は `JP`）
4. 「はじめる」または `Start` を押す → カメラの許可を求められる

言語切替は開始前だけ表示する。選んだ言語は端末に保存され、ページを開き直しても
同じ言語で出る（プライベートブラウズなど保存できない環境では毎回 `JP` に戻る）。
開始後の接続状態、警告、キャリブレーション、エラー、ガイド付き収録の指示は、選んだ
言語で表示される。ブラウザ自身が出すカメラ許可や証明書警告の言語は端末の設定に従う。

証明書の承認は、ブラウザによって場所が違う。

| ブラウザ | 操作 |
|---|---|
| iOS Safari | 「詳細を表示」→「このWebサイトを閲覧」 |
| iOS Chrome / Edge | 「詳細設定」→「アクセスする（安全ではありません）」 |
| Android Chrome | 「詳細設定」→「アクセスする（安全ではありません）」 |
| PC Chrome / Edge | 「詳細設定」→「<IP> にアクセスする（安全ではありません）」 |

「はじめる」を押させているのは、**一度ユーザー操作を挟まないと音を鳴らせない**
ため（自動再生の制限）。ここで音の準備をしている。

## 基準の測定

繋がると画面下の点が緑になり、送信数が増える。流れは次のとおり。

1. **準備（4 秒）** 「まもなく基準を測ります」。この間に端末を固定する
2. **測定の開始** 短い合図音が 1 回鳴る。ここから**前方を見る**
3. **測定の完了** 上がる 2 音が鳴る。以後、判定が始まる

前方を見ている間は画面を読めないので、始まりと終わりは音で知らせる。端末を見て
基準を取ると、前を見た瞬間から姿勢のずれが常に乗り、警告が出続ける。

測定が進まないときは、画面に理由が出る。

| 表示 | 対処 |
|---|---|
| 顔が映っていません | カメラの向きを直す。映るまで測定は進まない |
| 頭が動いたので測り直しています | 前方を見て止まる。2 回まで取り直し、それでも動くならそのまま確定する |

**ページを開き直すと、基準を捨てて測り直す。** 別の人に替わったり置き方が変わったり
した可能性があるため。通信が切れて自動で繋ぎ直しただけなら、基準はそのまま使う。
人が交代したときは「測り直す」を押してもよい。

## 画面の見かた

出るのは**警告・測定の案内・収録の指示だけ**。正常時は何も表示しない。常時何か
出していると、警告が出たときの変化に気づきにくい。動いていることは緑の点と
送信数で分かる。

警告は画面中央に文言で出す。授業で使うので、点滅や画面の縁取りはしない。

- 見出し: 「眠気が強いです」「脇見の兆候があります」など。段階は上端の線とアイコンの色で分ける（MEDIUM は黄土色、HIGH は赤）
- 2 行目: 原因。「まばたきが遅い」「前方を見ていない時間が長い」など
- 顔を見失ったときは「顔が映っていません」と出す。見失いは眠気の軸に入っているので、音は眠気と同じ
- 同じ警告は最低 1.5 秒出し続ける。判定は毎秒 20〜30 回届き、軸や段が細かく入れ替わるので、そのまま描くと読めない

ブラウザ版はストレスを判定しない（心拍の上がり幅が小さく参考にしかならず、安静基準に
数分かかるため）。判定するのは眠気・脇見・注意散漫の 3 つ。

警告音は PC 版と同じ形で、**音だけで何の警告か分かる**。同じ「ピー」の音色で、鳴らす数と
長さを変えてある。開始画面の「警告音を聞く」で、始める前に 3 つを聞き比べられる。

| 軸 | 音 |
|---|---|
| 眠気 | 長めのピーを 2 回（ピーピー） |
| 脇見 | 短いピを 3 回（ピピピ） |
| 注意散漫 | さらに短いピを 5 回、速く（ピピピピピ） |

MEDIUM は小さく一定間隔（既定 5 秒）で、HIGH は通常の音量で鳴らし、続く間は
鳴らすたびに間隔を詰める（下限 1.5 秒）。間隔は `config/browser.yaml` の
`feedback.alert_cooldown_seconds` などで変えられ、鳴らす時点は PC 側が決めて送る。
振動は音と同じ時点でだけ鳴らす。

画面下の状態表示が黄色になったら異常。

| 表示 | 意味 |
|---|---|
| 切断 — 再接続します | 通信が切れた。自動で繋ぎ直す。出ていた警告は消す |
| 判定が届いていません | 繋がっているが PC から判定が 3 秒以上来ない。PC 側を確認する |

## 対応と制限

| | 動くか |
|---|---|
| カメラ・送信・判定表示・音 | どのブラウザでも動く |
| マナーモード中の音 | iOS 17 以降の Safari は鳴る。それより古い iOS では消音スイッチで消える |
| 振動 | 対応している端末だけ（iOS は Vibration API 非対応） |
| 画面スリープ防止 | Wake Lock 対応ブラウザだけ。非対応なら手動で設定を切る |

- **ブラウザを前面に保つ必要がある。** 裏に回ると撮影が止まる。前面に戻れば、カメラ・音・スリープ防止を持ち直す
- **縦持ち・横持ちはどちらでもよい。** 途中で回しても、送る映像は歪まない
- **同時に 1 台。** 2 台目が繋ぐと古い方が切れる
- **無線が混むと送信を間引く。** 送り切れていない映像がある間は次を撮らないので、遅れは溜まらない

## 繋がらないとき

| 症状 | 原因 |
|---|---|
| ページが開かない | ファイアウォール、または IP 違い。同じ Wi-Fi にいるか確認。案内の別の URL も試す |
| 証明書の警告から進めない | 「詳細」系のリンクを押す。「戻る」だけだと進めない |
| カメラが出ない | `http://` で開いている。`https://` であること |
| 緑にならない | ページは開けているので TLS は通っている。`scripts\demo.bat --verbose` で PC 側のログを見る |
| 判定が変 | 「測り直す」を押す。測定中に前方を見ていなかった可能性 |
