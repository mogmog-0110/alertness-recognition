# ブラウザ版の使い方

アプリを入れずに、端末の Safari で URL を開くだけで使う。判定は PC 側が行い、
端末はカメラとスピーカーだけを担う。

## 1 回だけの準備（PC 側）

**証明書を作る。** iOS Safari は HTTPS でないとカメラを許可しない。LAN 内で
使うだけなので自己署名で足りる。

```bash
ipconfig                                  # IPv4 アドレスを控える (Windows)
python scripts/make_cert.py --host 192.168.1.10
```

IP を証明書に入れるのは、iOS が「アドレスと一致しない証明書」を強く拒むため。
**PC の IP が変わったら作り直す。**

**ファイアウォールで 8765 の受信を許可する。** ここで詰まると「繋がらない」
という症状になるが、原因が見えにくい。

## 起動（PC 側）

```bash
python -m alertness --config config/browser.yaml
```

次の 2 行が出れば待ち受けている。

```
[iphone] 待ち受け wss://0.0.0.0:8765
[iphone] ブラウザ版: https://<このPCのIP>:8765/
```

収録するときは `--guided --protocol acted_long --rounds 1 --record --subject <名前>`
を足す。

## 接続（端末側）

1. Safari で `https://<PCのIP>:8765/` を開く
2. 証明書の警告 →「詳細を表示」→「このWebサイトを閲覧」（初回だけ）
3. 「はじめる」を押す → カメラの許可を求められる

「はじめる」を押させているのは、iOS が**一度ユーザー操作を挟まないと音を鳴らせない**
ため。ここで音の準備をしている。

繋がると画面下の帯が緑になり、送信数が増える。接続してから 4 秒後に基準の測定が
始まるので、**その間は前方を見る**。端末を見て基準を取ると、前を見た瞬間から
姿勢のずれが常に乗り、警告が出続ける。

## 画面の見かた

出るのは**警告とキャリブの案内だけ**。正常時は何も表示しない。常時何か出していると、
赤い警告が出たときの変化に気づきにくい。動いていることは接続の緑で分かる。

## できないこと

- **振動** — iOS Safari は Vibration API に非対応。警告は画面と音のみ
- **バックグラウンド** — Safari を前面に保つ必要がある。裏に回ると止まる
- **同時に複数台** — 1 台想定。2 台目が繋ぐと古い方が切れる

## 繋がらないとき

| 症状 | 原因 |
|---|---|
| ページが開かない | ファイアウォール、または IP 違い。同じ Wi-Fi にいるか確認 |
| 証明書の警告から進めない | 「詳細を表示」を押す。「戻る」だけだと進めない |
| カメラが出ない | `http://` で開いている。`https://` であること |
| 緑にならない | ページは開けているので TLS は通っている。サーバのログを見る |
